## 0. 개발에 사용한 AI 도구·프롬프트

| 도구 | 용도 |
|------|------|
| **Cursor (Agent)** | 기획 문서화, 벤치마크 정리, 게임 루프/Director 구현, 밸런스·버그 수정, PDF/데모/ZIP 패키징 |
| **브라우저 자동화 (Playwright)** | `?demo=1` 자동 플레이 녹화 → 시연 영상 |

### 대표 프롬프트 패턴 (요약)
1. **Observe:** “스팀 인기작에서 이식 가능한 재미 요소만 추출해 표로 정리”
2. **Decide:** “NAN 심사용으로 AI Director가 ‘도구 사용’이 아니라 ‘연출 시스템’임을 증명하는 설계”
3. **Rebuild:** “Phase/Memory/Budget/Why UI를 구현하고 PEAK_FADE에서 spawn 억제”
4. **Verify:** “playtest로 Safe/Elite 클리어율 확인하고 softlock 수정”

→ 산출물은 코드(`game/game.js`)와 Why/Run Report UI로 검증 가능합니다.

---

## 1. 인게임 AI Director (핵심)

Director는 **Observe → Decide → Act → Explain** 루프입니다.

| 단계 | 입력 | 출력 |
|------|------|------|
| Observe | Intensity, Style, Memory, HP, threat | 상태 벡터 |
| Decide | Phase 규칙 + budget | Action 후보 |
| Act | spawn / elite / heal / suppress | 월드 변경 |
| Explain | **Why 패널** + Timeline + Run Report | 심사·플레이어 가독성 |

---

## 2. Phase 테이블 (L4D식)

| Phase | 진입 | 금지/허용 | Why 예시 |
|-------|------|-----------|----------|
| BUILD | 런/방 시작 | top-up pack | `BUILD top-up · budget-12` |
| SUSTAIN_PEAK | intensity peak | elite 개입 | `Style 지속 · Peak · Elite` |
| PEAK_FADE | sustain 종료 | **spawn 억제** | `PEAK_FADE · spawn 억제` |
| RELAX | fade/Safe | heal 우선 | `RELAX · HP<75 · Heal` |

---

## 3. Memory → Why

| Memory | 조건 | Action | Why |
|--------|------|--------|-----|
| No-Hit | 직전 방 무피격 | Elite Pack | `Memory No-Hit · budget 28` |
| Heavy | 피격≥35 | Heal | `Memory 다수 피격 · Heal` |
| Style | Aggressive/Cautious/Mobile | 스폰 가중 | `Style → Mobile` |
| Fork | Safe/Elite | 방 변이 | `플레이어 고위험 선택` |
